# OliTechs Print and Export Audit — Phase 1

**Repository:** `olitechs/olitechpmspos`  
**Branch:** `fix/real-print-export` (created from `main` at `e8817c4`)  
**Audit mode:** read-only static source, tests and migration inspection. No production data was queried or modified. `v6/` is an inactive historical copy and is not treated as active root-app behavior.

## Audit summary

The active app has three screen/document defects that should be repaired first: transactional Sales Report `Print` calls `window.print()` on the application DOM; Folio `Print statement` does the same; Room Planner `Download PDF` rasterizes the planner DOM with html2canvas and then embeds the image in jsPDF. The separate payment-receipt popup is a small customer document, but still calls browser `window.print()` rather than offering a generated PDF. In contrast, Shift Report has a real multi-sheet XLSX export and its `Re-print`/`Print & Close Shift` actions intentionally use the thermal printer pipeline.

Several labels from the requested baseline are not dedicated reports or controls in the current product. Monthly Sales by Item, by Category, by Shift, standalone Sales by Payment Type, X/Z, and end-of-day reports were not found as dedicated screens. Arrivals/departures, stock counts, wastage, purchases, transfers, employee directory and audit-log pages have no print/export action in the active screens reviewed. Those are recorded as missing capabilities, not as existing broken screen-print buttons. The existing primary Store movement report and Shift Report XLSX paths are genuine data exports; the former is capped at 500 rows and includes a staff display name.

## Special separation and audit caveats

- Never route POS receipts, kitchen/bar tickets, ESC/POS, local Print Agent (`127.0.0.1:8631`), or Shift Report thermal output through the document engine. Preserve their existing implementations unless a specific bug is proven.
- `window.print()` found in active report/document paths is at least `src/components/modules/Reports.jsx`, `src/components/modules/Folio.jsx`, and `src/components/pms/RoomPlanner.jsx`. RoomPlanner also uses html2canvas/jsPDF screenshot capture.
- Real workbook exports found include `src/services/shiftService.js` and primary Store movement XLSX in `src/services/inventoryService.js`. Shift XLSX must be retained and hardened, not replaced with page capture.
- The active Sales Summary settings tab is a placeholder, monthly subreports and X/Z/EOD screens are absent, and requisitions lack a backing schema/workflow. Adding exports requires a real data source first; no zero rows or guessed queries should be presented as report output.
- Phase 1 was a source-only audit. Authenticated browser checks, large live dataset validation, the PDF screenshot comparison and production DB reconciliation require an authorized test property/session and are not inferred from static review.
